# CLAUDE.md

Guidance for Claude Code (claude.ai/code) working in this repository.

**Read [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) first.** It is the living
description of how the site is built and why, including the decisions log. This
file is only the parts specific to working here.

## Commands

- `pnpm dev` — watch, rebuild, serve on localhost:3000 with live reload
  (`framework/dev.ts`, the only file allowed to use `Bun.*`). No Fast Refresh;
  an edit reloads the page.
- `pnpm build` — the production build under Node (`node scripts/build.mjs`).
  This is what Vercel runs.
- `pnpm build:bun` — the same build under Bun (`bun run build.ts`). Faster
  locally, byte-identical output.
- `pnpm check` — `tsc --noEmit`.
- `pnpm lint` — `oxlint .` then `oxfmt --write`. Must exit 0.
- `pnpm test` — the platform check. `bun run`, never `bun test`.
- `pnpm gate` — build, then compare the output against `docs/snapshot.json`.
  Must print `OK`.
- `pnpm snapshot` — build and rewrite `docs/snapshot.json`. Only when you mean
  to change the output; review the diff and say why in the commit.

Package manager is pnpm 9.15.9. Node 24 (`engines`) or Bun both work.

Run `pnpm check`, `pnpm lint`, `pnpm test` and `pnpm gate` before reporting a
change as done.

## The gate

`docs/snapshot.json` is one row per route: title, description, canonical, OG
image and noindex in plaintext, plus hashes of the prose and the code blocks,
plus the partial's byte count. A removed route, a changed field and an
undeclared document in the output are all fatal. A new route is informational,
so **adding a post or a note does not fail the gate**.

The diff is meant to be readable. If accepting a change means a wall of hash
churn you cannot explain, that is the signal, not a formality.

## Content

- Blog posts are MDX in `posts/`, notes are MDX in `notes/`. Frontmatter drives
  everything; `published: false` excludes a file from the site, the feed, the
  sitemap and the search index.
- External posts and project data live in `framework/content/index.ts`.
- The feed, sitemap, robots.txt and search index are generated by
  `framework/platform/feeds.ts`. There is no separate RSS script.
- To add an MDX component, put it in `app/mdx/static-components.tsx` if it is
  static, or `app/mdx/island-components.tsx` with a matching island in
  `app/islands/` if it needs to be interactive.

## Rules that are easy to break

- **`framework/shared/**` may import nothing but node builtins and React
  types.** The build, the client bundle and `tools/` all reach those three
  files. There is no lint rule for it (oxlint has no `no-restricted-imports`);
  each file says so in its docblock.
- **Nothing the client bundle reaches may import `node:fs` or gray-matter.**
  Anything shared between the build and an island has to be a leaf module, in
  `framework/shared/` or `app/lib/` depending on which side owns the concept.
  That is why `entryHref`, `POPULAR_SLUGS`, `transitionName` and the window
  styles live in one of the two.
- **`app/` imports the framework as `@framework/*`**, never by relative depth.
  `framework/` stays relative internally. `tools/` stays relative with explicit
  `.ts` extensions, because it runs unbundled where the alias may not resolve.
- **Feature detection, never user-agent sniffing.** No `navigator.userAgent`,
  `platform`, `vendor` or brand string anywhere in `framework/` or `app/`.
  The native-navigation gate needs all three of `supports('speculationrules')`,
  `'prerendering' in document` and `'PageRevealEvent' in window`: WebKit
  hardcodes the first to true for prefetch-only support, so dropping the second
  sends iOS Safari down the native path and its loading bar comes back.
- **A new stylesheet needs an entry in `PLAIN_SHEETS`** in `build.ts`, with an
  attribute-shaped marker (`class="thing-`, not `thing`). A sheet with no entry
  ships on no page at all.
- **Class names are written scoped.** There is no CSS-module compiler. A
  component and its island use the same literal strings from the same `.css`
  file.
- **`vercel.json` is generated** by `framework/platform/vercel.ts` on every
  build. Editing it by hand is silently reverted.
- **The runtime is inlined into every page on purpose.** Chrome skips the
  inbound half of a cross-document view transition when the destination has an
  external module script in `<head>`. That is why it has a size budget.
- **`app/styles/global.css` carries a trimmed copy of Tailwind's preflight.**
  Recheck it against `node_modules/tailwindcss/preflight.css` on a Tailwind
  major upgrade.

## Code conventions

- **TypeScript**: strict, no `any`.
- **Formatting**: no semicolons, single quotes, 2-space indent, 80 cols (oxfmt).
- **Imports**: extension-less everywhere under `app/` and `framework/`; path
  alias `@*` maps to `./app/*`. `tools/` runs unbundled and may use `.ts`
  extensions.
- **CSS**: Tailwind utilities first; a plain pre-scoped `.css` file for
  component rules utilities cannot express.
- **Comments** should record a trap you would otherwise fall into again, not the
  history of how the code got here.
- **Content files**: YAML frontmatter with `title`, `date`, `description`.
